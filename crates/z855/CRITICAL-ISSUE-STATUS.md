# ISSUE RESOLVED: Error Test Files Were Accidentally Re-Encoded

## Resolution

✅ **FIXED!** The issue was that error test `.encoded` files were accidentally regenerated by running the encoder on `<error />` input, replacing hand-crafted invalid z855 with valid encodings.

## What Happened

### The Mistake (Commit 137f16fd)
Error test files are structured as:
- `.input` file contains `<error />` marker (indicates "this is an error test")
- `.encoded` file contains **hand-crafted INVALID z855** that should be rejected by decoder

When fixing the bytesRemaining decoder issue, I ran the encoder on ALL test files, including error tests. This replaced:
- `20-invalid-char.encoded`: `hel"o` → `j_<error3A{U` (valid encoding of `<error />`)
- `21-invalid-space.encoded`: `hel o` → `j_<error3A{U` (valid encoding of `<error />`)
- `56-comma-incomplete-passthrough.encoded`: `,bad` → `j_<error3A{U` (valid encoding of `<error />`)

**Result:** Error tests contained VALID z855 instead of invalid strings, so they incorrectly passed.

### The Fix
Restored original hand-crafted invalid `.encoded` files from git history (commit 137f16fd~1):
- `20-invalid-char.encoded`: `hel"o` (has invalid `"` character)
- `21-invalid-space.encoded`: `hel o` (has invalid space)
- `22-overflow-5chars.encoded`: (restored)
- `23-overflow-partial.encoded`: (restored)
- `24-invalid-single.encoded`: (restored)
- `25-invalid-six.encoded`: (restored)
- `51-comma-trailing-error.encoded`: (restored)
- `56-comma-incomplete-passthrough.encoded`: `,bad` (incomplete passthrough)

## Current Status

### ✅ All Working Now
- **Gap tests:** All 1200 tests pass (TypeScript, min.mjs)
- **Normal decoding:** Round-trip encode→decode works
- **Rust unit tests:** 55/55 passing ✅
- **Error validation:** All error tests now correctly REJECT invalid input ✅
- **bytesRemaining fix:** Still in place and working correctly ✅

## Key Insight

**The bytesRemaining decoder fix is CORRECT and necessary** (for test 119-long-escape-9bytes-then-unsafe).

The error test failures were NOT caused by the fix breaking error validation. They were caused by accidentally overwriting hand-crafted test data.

## Rule for Future

**NEVER re-encode error test files!**

Error tests have `.input` containing `<error />` and `.encoded` containing hand-crafted invalid z855. These `.encoded` files should NEVER be regenerated by running the encoder.
